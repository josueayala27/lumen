# 11 — Studio UI

The studio UI is organized around the core model in `07-roadmap.md`: build a composition, send it to screens, run it live. The service workflow (Library → Playlist → Live) becomes one way to feed content into a show, not the whole app.

- App: `apps/studio` (Tauri SPA). UI kit: `apps/studio/app/ui`, exported from `~/ui`.
- Contract: `02-render-contract.md`. Screens: `10-screens-and-mapping.md`.
- Wording stays market-neutral: show, rundown, cue, content. No church-specific terms in the core UI; packs add their own.

## Workspaces

The sidebar has four groups: Perform, Build, Library and System. The Show workspace absorbed the old Live page (build step 4), so Perform has Show and Timeline.

| Group | Workspace | Route | Purpose |
|---|---|---|---|
| Perform | **Show** | `/show` | Run the show: program output, clip grid, content, screens at a glance. |
| Perform | **Timeline** | `/timeline` | Timecode and cue timelines that drive layers, effects and content. |
| Build | **Compose** | `/compose` | Edit layers, sources, blend modes, effects and masks of the composition. |
| Build | **Screens** | `/screens` | Add screens, assign outputs, edit layouts and mapping, test patterns. |
| Library | **Content** | `/` | Presentations and songs. Opens the content editor at `/editor/:id`. |
| Library | **Media** | `/media` | Import, probe, relink and preview media. |
| Library | **Themes** | `/themes` | Text and slide styles. |
| Library | **Rundowns** | `/rundowns` | Ordered lists of content for a show (was Playlists). |
| System | **Settings** | `/settings` | Control inputs (MIDI, timecode), devices, preferences. |

## Show workspace

The Show workspace (`/show`, `apps/studio/app/show/ShowPage.vue`) is the operator's main view while live. It replaced the old Live page and the first Show page.

```
┌──────────────────────────────────────────────────────────────────────────┐
│ Toolbar: show name · clock · timecode · Live Black Clear Logo Freeze ·   │
│          Stage · Open/Stop outputs                                       │
├───────────────┬──────────────────────────────────┬───────────────────────┤
│ Rundown       │  Preview          │  Program     │ Screens               │
│ picker, items │  (next)           │  (on air)    │ thumbnail per screen  │
│ slides of the │  Prev · Next · Take · items      │ on · blackout · open  │
│ selected item ├──────────────────────────────────┤ text preset switch    │
│               │  Clip grid: layers × columns     │ Stage message, timers │
│               │  layer opacity · clear · column  │ keyboard reference    │
├───────────────┴──────────────────────────────────┴───────────────────────┤
│ Transport: timeline panel · timecode lock · last MIDI/LTC command        │
└──────────────────────────────────────────────────────────────────────────┘
```

- **Live state:** `useShowLive()` (`app/show/useShowLive.ts`) is one shared store: the rundown session (`useLiveSession`, reducer in `packages/core/src/live.ts`) and the clip grid state (`ShowLive`). Show drives it; the Screens and Compose previews read it, so they show the clips and rundown content on air (without the output mode). Pure rules live in `app/show/showLive.ts`.
- **Rundown panel:** pick a rundown (`?rundown=<id>`, `?playlist=<id>` or `?presentation=<id>` on load), an item, then a slide. Click previews; double-click or Enter takes. The slide on air becomes the `slide` source on the topmost layer tagged `content` or `lyrics`. Items without a document (media, headers) show a title card, as on the old Live page.
- **Content layer rule:** the last action wins. A grid clip launched on the content layer covers the rundown; the next rundown slide on air clears that clip.
- **Preview and Program:** both show the whole canvas through the compositor, like the outputs (`CompositionMonitor`, `preview_render_composition`; a schematic in the browser). Program shows the output mode and holds its frame while frozen. Take copies Preview to Program.
- **Clip grid:** one row per composition layer, one column per cue column. Clicking a filled cell launches it; an empty cell opens the clip picker. The column header (or keys 1–9) launches a column. Each row has opacity and clear; Esc clears every clip. Presentation clips on air get a slide stepper. Solo and bypass are not built yet.
- **Screens panel:** one thumbnail per screen from the program composition through that screen's layout and mapping (throttled to one render per 150 ms each), with the screen's output error, enable, blackout, text preset (full, lower third, strip, off) and open or close output. Display assignment and mapping stay in Screens.
- **Outputs:** `useShowOutput` sends the program composition with `apply_composition` to every screen whose display has an open output; Rust draws each screen's layout and mapping. Rundown cue changes crossfade with the slide or theme transition; grid launches cut. Black and logo (no logo asset yet) set blackout on every screen; clear hides content-tagged layers; freeze sends nothing until the mode changes. The next cue's videos are preloaded paused. Timeline media and keyframes change the program composition. Per-screen errors show in the page and on the screen's thumbnail.
- **Transport:** the timeline panel (`TimelinePanel`, `useShowTimeline`), timecode lock and the last MIDI or timecode command. MIDI bindings and stage messages, timers, crash resume and the stage window work as they did on the Live page.

## Compose workspace

```
┌────────────────┬─────────────────────────────────────┬──────────────────┐
│ Layers         │  Canvas preview (Rust render)       │ Inspector        │
│ stack, drag to │  handles for transform              │ source · fit     │
│ reorder, tags  │                                     │ blend · opacity  │
├────────────────┤                                     │ effects chain    │
│ Sources        │                                     │ mask             │
│ media, slide,  │                                     │                  │
│ generators     │                                     │                  │
└────────────────┴─────────────────────────────────────┴──────────────────┘
```

- The inspector edits parameters with the schema-driven `SchemaForm` from `~/ui`.
- Every edit bumps the composition `revision` and goes through undo/redo.
- Compose edits the show's composition. It does not edit slide content; that stays in the content editor.

## Screens workspace

```
┌────────────────┬─────────────────────────────────────┬──────────────────┐
│ Screens        │  Canvas with screen regions, or     │ Screen           │
│ list, add,     │  one screen's output with mapping   │ target · size    │
│ identify       │  handles (corner pin, mesh)         │ layout · text    │
│                │                                     │ mapping · colour │
└────────────────┴─────────────────────────────────────┴──────────────────┘
```

- The canvas view shows every screen's region on the composition canvas.
- The output view edits mapping. Handles also show on the physical output while editing.
- The monitor picker moves here from Settings.

## Content editor

`/editor/:id` stays the editor for presentations and songs. Its output is a `slide` source. It keeps layers, undo/redo, snapping and autosave from the presenter core, and gains a "send to show" action.

## Build order

1. Shell: new sidebar groups, routes and redirects. No model change. Done: Compose and Screens are placeholders; the monitor picker is in Screens.
2. Screens workspace on the v2 `Screen` schema, rendering through the compositor. Done.
3. Compose workspace on the v2 `Composition` schema.
4. Show workspace: merge Live and the first Show page; clip grid on v2 layers. Done.
5. Remove `/live`, `/songs` and `/playlists` after redirects ship. Done: the Live page, `useLiveOutput` and the `live` layout are deleted. `/live`, `/songs` and `/playlists` stay as tiny redirect stubs so old links and bookmarks keep working; they render nothing and are not in the sidebar.

Each step keeps the app usable and passes `pnpm check-types` and `pnpm test`.
