# 11 — Studio UI

The studio UI is organized around the core model in `07-roadmap.md`: build a composition, send it to screens, run it live. The service workflow (Library → Playlist → Live) becomes one way to feed content into a show, not the whole app.

- App: `apps/studio` (Tauri SPA). UI kit: `apps/studio/app/ui`, exported from `~/ui`.
- Contract: `02-render-contract.md`. Screens: `10-screens-and-mapping.md`.
- Wording stays market-neutral: show, rundown, cue, content. No church-specific terms in the core UI; packs add their own.

## Workspaces

The sidebar has three groups and Settings.

| Group | Workspace | Route | Purpose |
|---|---|---|---|
| Perform | **Show** | `/show` | Run the show: program output, clip grid, content, screens at a glance. |
| Perform | **Timeline** | `/timeline` | Timecode and cue timelines that drive layers, effects and content. |
| Build | **Compose** | `/compose` | Edit layers, sources, blend modes, effects and masks of the composition. |
| Build | **Screens** | `/screens` | Add screens, assign outputs, edit layouts and mapping, test patterns. |
| Library | **Content** | `/` | Presentations and songs. Opens the content editor at `/editor/:id`. |
| Library | **Media** | `/media` | Import, probe, relink and preview media. |
| Library | **Themes** | `/themes` | Text and slide styles. |
| Library | **Rundowns** | `/rundowns` | Ordered lists of content for a show (was Playlists). |
| — | **Settings** | `/settings` | Control inputs (MIDI, timecode), devices, preferences. |

## Show workspace

The Show workspace is the operator's main view while live. It replaces the old Live page and the first Show page.

```
┌──────────────────────────────────────────────────────────────────────────┐
│ Toolbar: show name · clock/timecode · BPM · mode (Live Black Clear Freeze)│
├───────────────┬──────────────────────────────────┬───────────────────────┤
│ Rundown       │  Preview          │  Program     │ Screens               │
│ content list  │  (next)           │  (on air)    │ thumbnail per screen  │
│ slides of the ├──────────────────────────────────┤ enable · blackout     │
│ selected item │  Clip grid: layers × columns     │ layout quick switch   │
│               │  layer opacity · solo · bypass   │                       │
├───────────────┴──────────────────────────────────┴───────────────────────┤
│ Transport: timeline position · cue GO (Wave E) · MIDI/timecode status    │
└──────────────────────────────────────────────────────────────────────────┘
```

- **Rundown panel:** the active rundown. Selecting a slide sends it to the `slide` source on the layer tagged `content` or `lyrics`, through the live state in `packages/core/src/live.ts`.
- **Preview and Program:** Preview shows the next state; Program shows the canvas as rendered. Take copies Preview to Program.
- **Clip grid:** one row per composition layer, one column per cue column. A cell holds a source. Clicking a cell sets the layer's `sourceId` with the layer transition. Launching a column triggers every layer.
- **Screens panel:** one thumbnail per screen from the Rust renderer, with enable, blackout and layout switch.

## Compose workspace

```
┌────────────────┬─────────────────────────────────────┬──────────────────┐
│ Layers         │  Canvas preview (Rust render)       │ Inspector        │
│ stack, drag to │  handles for transform              │ source · fit     │
│ reorder, tags  │                                     │ blend · opacity  │
├────────────────┤                                     │ effects chain    │
│ Sources        │                                     │ mask             │
│ media, slide,  │                                     │                  │
│ generators     │                                     │                  │
└────────────────┴─────────────────────────────────────┴──────────────────┘
```

- The inspector edits parameters with the schema-driven `SchemaForm` from `~/ui`.
- Every edit bumps the composition `revision` and goes through undo/redo.
- Compose edits the show's composition. It does not edit slide content; that stays in the content editor.

## Screens workspace

```
┌────────────────┬─────────────────────────────────────┬──────────────────┐
│ Screens        │  Canvas with screen regions, or     │ Screen           │
│ list, add,     │  one screen's output with mapping   │ target · size    │
│ identify       │  handles (corner pin, mesh)         │ layout · text    │
│                │                                     │ mapping · colour │
└────────────────┴─────────────────────────────────────┴──────────────────┘
```

- The canvas view shows every screen's region on the composition canvas.
- The output view edits mapping. Handles also show on the physical output while editing.
- The monitor picker moves here from Settings.

## Content editor

`/editor/:id` stays the editor for presentations and songs. Its output is a `slide` source. It keeps layers, undo/redo, snapping and autosave from the presenter core, and gains a "send to show" action.

## Build order

1. Shell: new sidebar groups, routes and redirects. No model change.
2. Screens workspace on the v2 `Screen` schema, rendering through the v1 adapter.
3. Compose workspace on the v2 `Composition` schema.
4. Show workspace: merge Live and the first Show page; clip grid on v2 layers.
5. Remove `/live`, `/songs` and `/playlists` after redirects ship.

Each step keeps the app usable and passes `pnpm check-types` and `pnpm test`.
